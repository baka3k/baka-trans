# Phase 09: HY-MT M5 POC and Decision Gate

## Context

The supplied Hugging Face example is Python/PyTorch code, while the product translation path is Rust and currently calls Ollama. Before adding a new managed runtime, prove that the exact model can deliver useful realtime Japanese-to-Vietnamese translation on the current Apple M5/24 GB machine and that its Python runtime can be packaged.

This phase is a hard gate. It may create an isolated POC and evidence, but must not replace the production Ollama path or change the default engine.

## Requirements

- Use `tencent/HY-MT1.5-1.8B` at one immutable revision and record all model/runtime versions.
- Use an isolated Python environment; never install into or depend on `/usr/bin/python3`.
- Probe MPS explicitly and record actual device, dtype, model-load time, warm latency, memory, and generated token counts.
- Compare deterministic greedy decoding with the model-card generation settings on the same JA→VI corpus.
- Verify the exact prompt/chat-template and suffix-only decode behavior.
- Run with network disabled after the model is cached locally.
- Produce a same-platform one-folder packaging spike and measure its size/startup behavior; it need not yet be wired into Tauri.
- Record Tencent license/territory assumptions for internal Vietnam use.

## Implementation Steps

1. Pin Python, Transformers 4.56.1, PyTorch, safetensors, and Hugging Face Hub versions in an isolated `uv` project; add Accelerate only if the chosen loading API actually requires it.
2. Download the candidate revision into a dedicated POC directory and record all file sizes/digests without modifying the product model store.
3. Implement a minimal runner that loads once, probes MPS, formats the official prompt, generates, slices input tokens, and emits structured timings/device data.
4. Build a representative corpus of at least 30 Japanese utterances covering names, numbers, technical meeting vocabulary, short/long segments, punctuation, mixed English, and malformed/empty input boundaries.
5. Compare greedy and recommended generation settings using human bilingual review against the current TranslateGemma/Ollama result; do not require byte-identical translations.
6. Run cold-load, repeated warm, cancellation/timeout experiment, offline inference, and a 30-minute sustained loop while Whisper and selected TTS are also resident where practical.
7. Produce a PyInstaller one-folder spike; measure bundle bytes, startup/load success, nested native libraries, and code-signing implications.
8. Publish GO/CAUTION/STOP with raw commands, hardware/OS identifiers, measurements, failures, and the exact runtime/model pins proposed for Phase 10.

## Risks

- Some HY-MT operations may fail or fall back unexpectedly on MPS/BF16. Treat fallback as evidence and do not hide it.
- POC cache/runtime files are multi-gigabyte. Use explicit app/POC paths and document cleanup without destructive broad commands.
- A fast text-only benchmark may not represent contention with Whisper and TTS. Include combined-process evidence before GO.
- Human translation review can be subjective. Use fixed acceptance dimensions and preserve source/baseline/candidate outputs.

## Success Criteria

- Warm inference produces valid Vietnamese with no explanation framing or empty result for every accepted corpus input.
- The 30-minute run has zero crashes and no sustained production rate slower than the fixture utterance rate; absolute p50/p95 are recorded.
- Combined memory remains below 80% of 24 GB with no macOS memory-pressure escalation; cold load and sidecar peak RSS are recorded.
- Offline inference succeeds after local installation and no transcript text is sent to a network service.
- The one-folder runtime starts on the M5 machine and its measured size/signing constraints are acceptable for the internal build.
- **GO:** continue to Phase 10 with exact pins. **CAUTION:** schedule explicit mitigations before Phase 10. **STOP:** keep Ollama active and close Phases 10-15.
